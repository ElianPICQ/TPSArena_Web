# CLAUDE.md

Static showcase and download site for TPS Arena, served on the LAN at `http://<host-ip>:8080` (no local name: mDNS does not pass on the school Wi-Fi).
It also serves **TPS Arena Companion** (`app/`), a PWA under `/app/` where players see their stats, progression, achievements, match history and leaderboards, manage friends and chat with them. It is the site's only link to the backend: nginx proxies `/api/` to `backend/services/web-bff` and `/ws` (WebSocket) to Real-time, over the shared Docker network `tpsarena-web`.
The README, UI text and commit messages are in French.

## Commands

- `npm run dev`: Vite dev server. A plugin in `vite.config.ts` serves `/manifest.json`, `/releases/` and `/screenshots/` from the local folders, like the container does.
- `npm run dev:app`: the PWA alone on http://localhost:5174/app/, proxying `/api/` to the web-bff on `127.0.0.1:8006`.
- `npm run build`: `tsc --noEmit`, then the showcase build into `dist/`, then the PWA build (`vite.app.config.ts`, root `app/`) into `dist/app/`.
- `scripts/certificat.sh [IP]` (`certificat.ps1` on Windows): mkcert certificate for the host IP into `certs/`, then restarts the container. Rerun when the IP changes.
- `docker compose up -d --build`: production (host port `SITE_PORT`, default 8080; nginx listens on 80 inside the container).

## Architecture

- `docker/40-arena-manifest.sh` (POSIX sh, BusyBox) runs from the nginx image's `/docker-entrypoint.d/` and writes `manifest.json` (`builds.{windows,linux,macos}` = `{file,size,modified}` or `null`, plus `screenshots: string[]`). It then polls the mounted folders every `MANIFEST_REFRESH` seconds and regenerates the file when something changed. Keep `vite.config.ts` (dev) and `src/lib/manifest.ts` (types) in sync with it.
- `docker/site-locations.conf`: `manifest.json` is `no-store`, `/assets/` is immutable, `/releases/` is forced to download. Security headers live in `security-headers.conf` and are included in every location because `add_header` does not inherit.
- `src/components/NeonBackground.tsx` is a WebGL port of `TPSArena_Jeu/client/front/shaders/menu_background.gdshader`. Keep its constants identical to the Godot shader. The CSS fallback is in `.neon-bg__fallback`.
- The colors in `src/styles.css` come from `TPSArena_Jeu/client/front/scripts/ui/ui_theme.gd`, the panel and button styles (chamfered top-left and bottom-right corners, 12 px / 8 px) from `front/ui/theme/neon_theme.tres`. CSS draws a chamfer with `clip-path` plus an `::after` that redraws the diagonal in `--bc`: set `--bc`, never `border-color`, on those elements. The presentation (specialists, classes, bonuses, maps, modes) and controls content comes from the game's README, `front/data/classes/*.tres`, `scripts/inputs.gd`, `scripts/pickups.gd` and `scripts/maps/*`. Re-check them when the game changes.
- The showcase is served over plain HTTP, which is not a secure context, so `navigator.clipboard` is unavailable. `src/lib/clipboard.ts` falls back to `execCommand('copy')`.
- **HTTP or HTTPS:** `docker/35-arena-tls.sh` runs at each container start. With `certs/site.crt` + `site.key` (mkcert, local CA installed on the demo phones) it uses `nginx-https.conf`: the showcase on both ports, `/app/` and `/api/` redirected from HTTP to HTTPS (8443). Without them it uses `nginx.conf`, all HTTP. Locations are split into snippets (`site-locations.conf`, `app-locations.conf`, `app-redirect.conf`, `server-common.conf`); `@WEB_BFF@`, `@REALTIME@` and `@HTTPS_PORT@` are filled from env (`WEB_BFF_UPSTREAM`, `REALTIME_UPSTREAM`, `SITE_HTTPS_PORT`) by the script. `absolute_redirect off` because the host publishes other ports than the container's. No HSTS (it would cover the whole IP, game backend ports included). Never put mkcert's `rootCA-key.pem` in `certs/` or the image; `certs/` and the build context exclude it all.
- **The PWA** (`app/src`): hash routing (`#/succes`…), so the service worker only needs `/app/`. `lib/api.ts` keeps the access token in memory; the refresh token is an HttpOnly cookie set by the web-bff (`Path=/api/auth`). Refreshes go through one promise and a Web Lock, because Auth revokes every session when a rotated refresh token is reused (two tabs refreshing at once). `lib/realtime.ts` holds the WebSocket (`"client": "mobile"`, heartbeats, `auth` again before the access token expires, reconnect with backoff, back to login on 4001 `session_revoked` / 4003) and a small store (`useSyncExternalStore`): friends' presence, live messages, unread counts, toasts. Friend notifications bump `friendsVersion`, which reloads the friend list (`lib/friends.ts`, loaded once in `App`). API data is not cached by the service worker: `lib/cache.ts` keeps the last response of each screen per player in localStorage for offline use, cleared on logout. Error codes are translated in `lib/labels.ts` (same texts as the game's `ApiClient.ERROR_MESSAGES`), so are map names (`MapCatalog`) and achievements (`backend/services/stats/stats/progression.py`): update them when those change. `/manifest.json` is the showcase's build list, so the web manifest is `/app/app.webmanifest`.
- The Docker build stage works in `/src`, not `/app`: with `WORKDIR /app`, Vite built the PWA's `app/index.html` instead of the showcase.
